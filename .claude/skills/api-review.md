# API 接口审查

审查当前项目的 API 接口实现，检查以下规范：

## 检查项

### 1. RESTful 规范

- 资源路径是否使用小写复数名词，连字符分隔
- HTTP 方法是否正确：GET(查)、POST(增)、PUT(改)、DELETE(删)
- URL 是否包含动词（应该用名词）

### 2. HTTP 状态码

- 200: 成功
- 201: 创建成功
- 400: 参数错误
- 401: 未授权
- 403: 禁止访问
- 404: 资源不存在
- 500: 服务异常

### 3. 请求/响应格式

- 请求体是否使用 JSON
- 响应格式是否统一：`{ code, message, data }`
- 分页参数是否规范：`page`, `pageSize` 或 `limit`, `offset`

### 4. 项目特定规范

- 是否有 JWT 鉴权中间件
- 是否有参数校验
- 是否有错误处理中间件

## 输出格式

列出所有发现的问题，按严重程度排序：

- 🔴 严重：违反 RESTful 核心原则
- 🟡 警告：不符合最佳实践
- 🔵 建议：可优化项
